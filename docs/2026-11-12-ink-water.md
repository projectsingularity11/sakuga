# Ink, paper and cursor water

## Direction and references

The user requested Japanese professional print/ink character, dynamic cursor-driven gradients, water-like cursor feedback, light/dark modes and fast interaction. Used the design-taste frontend skill. Reviewed [TORII by Deividas Bielskis](https://dribbble.com/shots/27807312-TORII), whose description identifies sumi-e ink wash; its off-white/charcoal/earth palette informed the paper/ink direction. No reference artwork, branding or site code was copied. Sakuga keeps its own mark, artwork, navigation and discovery functionality.

GitHub primary-source review extends the earlier `research/motion.md` survey:

- [PavelDoGreat/WebGL-Fluid-Simulation](https://github.com/PavelDoGreat/WebGL-Fluid-Simulation): README and script configuration, MIT. Its dye/simulation buffers, pressure iterations, bloom and sunrays target a rich continuous simulation. Did not import its solver, promotional code or runtime.
- [sirxemic/jquery.ripples](https://github.com/sirxemic/jquery.ripples): README and distribution source. Reviewed float-texture/framebuffer capability checks, resolution controls, same-origin image limitations and pause/destroy lifecycle. Avoided requiring jQuery or rebinding remote anime artwork as WebGL textures. The initially guessed `src/` path returned 404; the actual `dist/` implementation was inspected.
- [tholman/cursor-effects](https://github.com/tholman/cursor-effects): README and ghost cursor implementation. Reviewed pointer-transparent canvas, finite particle lifetime and reduced-motion teardown. Sakuga authors a different optical ring wake, with no cursor sprites and no idle loop.
- [Shippori Mincho](https://github.com/google/fonts/tree/main/ofl/shipporimincho): verified SIL OFL. Self-hosted Latin subset, one weight, 28,520-byte WOFF2; license at `/licenses/shippori-mincho.txt`. Used on selected display headings, while existing Japanese sans body and technical controls retain readability. No font CDN or Japanese multi-megabyte font download.

The guessed Codrops InkTransition repository did not resolve and was not used. This research is source inspection, not a claim to have executed every upstream demo or reproduced Unseen's proprietary implementation.

## Implementation and budget

Two small mineral-color background fields ease toward the pointer using compositor transforms and a limited hue range. Artwork-derived pools remain. The optical cursor wake is an authored Canvas2D approximation of water highlights, not a physical fluid solver or distortion of page text. Eighteen ripples maximum, one-second lifetime, 45ms input sampling, maximum backing-store scale 1.25 and width 1600px. Fine mouse pointers only. Canvas work stops when ripples expire and clears on hidden/leave/unmount. Reduced motion or data saving skips the runtime; reduced transparency hides optical layers. Touch keeps native behavior. Cursor movement never sets React state.

Renderer code is split out with a dynamic import. The paper texture is a 329-byte local SVG tiled as a static background, rather than an animated full-screen noise filter. Removed the full-screen ambient backdrop blur. Existing lazy artwork, cached local home AVIF/WebP, demand-driven Lenis/Motion and the preceding production database speed fix are retained.

Appearance switch is available in public and private headers. A validated light/dark cookie supplies the server-rendered mode across routes and reloads. Account settings still support system mode; changing the settings mode clears the local override. Keyboard labels/focus states are explicit. No audio.

## Measurements and verification

Local Chromium, 1440×1000, fixture server, warmed page, 80 mouse positions with 16ms spacing: 193 water draw callbacks; median 0.5ms, p95 1.8ms, max 5.1ms main-thread callback time. After settling 1400ms, there were **zero additional draws** during the next 500ms. These numbers measure callback CPU time, not GPU compositing, low-end device performance, production CWV or an end-to-end speed improvement.

45 unit/database tests passed. Desktop/mobile browser coverage verifies layout, accessibility, session continuity, typography/reduced motion, smooth scrolling, persistent paper mode and canvas teardown. The new heading layout exposed a brittle scroll test that sampled absolute position after Playwright had scrolled a poster into view; it now measures wheel displacement from the starting position. Mobile paper-mode navigation uses a direct route visit rather than clicking a hidden closed-menu link. Both corrected flows passed on desktop/mobile.

Final checks: 45 unit/database tests, 14 unique selected browser cases across desktop/mobile, ESLint, TypeScript and the production build passed. Dark and paper viewport captures were visually inspected.
