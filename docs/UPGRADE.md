# Discovery, search and artwork upgrade

Observed causes: the previous search stripped punctuation and ordered all matches by popularity; it had no suggestions or ranked aliases. English titles were not stored separately in the baseline and title selection differed by surface. Every cover URL was accepted without measuring dimensions. The homepage was primarily promotional rather than discovery-oriented.

Implemented: Postgres normalized Unicode/punctuation search over all published titles/aliases, exact > prefix > substring > conservative trigram ranking, pagination and real genre/format/year/season/release/source-score filters. Query cache is bounded to 100 public catalog results / 30 seconds per server instance; client suggestions to 50 queries / 60 seconds. Suggestion requests debounce 300 ms, abort superseded work, and check generation before committing results. Errors are separate from empty results. Keyboard arrows/Enter/Escape, clear and full URL results are supported. This is bounded trigram retrieval, not a promise of complete typo matching.

English-first title resolution is shared by cards, details, lists and search. Official English is distinct from romaji/native; blanks fall through without translation. Existing saved title-language preferences are used for public browse and suggestions too. Provider English fields are progressively enriched; records without an official English title use romaji. User data was preserved.

Homepage feeds use distinct queries and fail independently. Existing backend list/progress/collection/theme workflows remain in place; saved discovery entries are fetched in one batch. No streaming controls were added. HD image errors fall back without repeated retries.

Original-source cover minimum: 720×1080; target: 1080×1620. Scheduled ingestion tries Kitsu original/large and AniList extraLarge, downloads with time/size limits, reads actual image headers, and records measured dimensions and check time. Only qualified sources are displayed. No upscaling is counted. **This is not full HD coverage:** an initial 166-record audit found 12 passing 720×1080, including two passing 1080×1620. An additional licensed higher-resolution artwork source is needed to meet the request for every title; unsupported titles remain explicit fallbacks. Search/list data is not hidden merely because artwork is missing.

Verification: 32 deterministic unit/provider/Postgres tests passed, including executing the actual search migration and verifying alias ranking, punctuation and anonymous moderation boundaries. Twenty fixture-backed Playwright checks passed at 375, 390, 768, 1280 and 1440 widths, including keyboard/accessibility and stale/clear/failure transitions. The test-only protocol server never enters the production app. Fixtures verify UI behavior, not production artwork coverage or signed-in browser flows. Hosted SQL checks found all requested example families; the nonsense query returned zero, and 'jujutsu kaisne' retrieved JUJUTSU KAISEN. Build/lint/typecheck passed before final small consistency edits; final release checks are recorded in the chat.

Remaining boundaries: full-catalog English/native metadata enrichment and high-resolution art sourcing, real inbox delivery/payment configuration from the prior delivery, and authenticated browser coverage. Existing database ownership/list persistence integration tests remain passing; no account data was reset. Account deletion remains disabled; this task did not authorize deploying that previously blocked capability.
